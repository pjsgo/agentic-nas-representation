## 문제와 관찰한 실패

생성된 블록은 선언된 학습 가능 자원 12개를 모두 `requires_grad=False`인 일반 텐서로 만들었습니다. 기존 텐서에 동일한 검증용 값을 복사한 뒤 비교하면 9개 조건 모두 연산 결과가 기준 구현과 같았습니다. 그러나 Parameter 유형 요건은 충족하지 못했습니다.

사전 고정한 명령행 검증기는 예상한 Module 인터페이스가 없는 일반 객체를 만나 실행 연결에도 문제가 있었습니다. 이 검증기 제약은 별도의 INCONCLUSIVE로 기록했습니다. 이를 이유로 독립적으로 확인한 Parameter 위반을 무시하지 않았습니다.

## 후속 실험 설계

공통 해석 규칙은 같게 두고 등록 선언 유무를 달리하는 두 조건의 실험을 준비했습니다. 두 조건 모두 새 후보는 아직 생성하지 않았습니다. 앞으로는 각 표현의 규칙 준수 여부와 두 조건에 공통으로 적용할 등록 상태 목표를 나눠 보고해야 합니다. 한 쌍의 결과만으로 일반적인 개선 효과를 단정할 수는 없습니다.

## 이 사례에서 얻은 점

텐서 값이나 그럴듯한 모듈 이름만 확인해서는 충분하지 않습니다. 실제 연산에 쓰이는 객체가 올바른 Parameter인지도 확인해야 합니다.

## 검증하지 않은 범위

전체 Transformer, 원본 Module 계층, 초기화, 학습·역전파, 자율 편집은 검증하지 않았다.
