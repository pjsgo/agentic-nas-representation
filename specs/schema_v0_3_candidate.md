# Representation Semantics v0.3 Candidate — revision 1
FROZEN_FOR_THIS_RUN. This is a normative additive interpretation contract, not an executable universal validator or a claim of coverage. The entire unmodified v0.2 snapshot remains normative for `representation_version: "0.2"`, including its PyTorch operator profile, Module identity, mutation and static shape meanings. This document governs new `representation_version: "0.3-candidate.1"` inputs. Unsupported constructs must be reported.

## Document and hierarchy
Required keys: `representation_version`, `operator_profile`, `architecture`, `architecture_entry`, `factors`, `dataflow`, `interface`. Optional keys: `resource`, `parameters`, `buffers`, `parameter_bindings`, `buffer_bindings`, `state`, `dependency`. Unknown computational fields require a schema delta. Descriptive annotations use only `description` strings and cannot define calculations.
`operator_profile` is either the original `pytorch_nn_2_2_1_v0_2` or `tensor_pytorch_2_2_1_v0_3_r1` defined below. The latter includes the original profile unchanged.

Factor IDs are globally unique identifiers matching `[A-Za-z_][A-Za-z0-9_]*`. Each factor has exactly one of `contains`, `operator`, `call`, `scan`. `contains` is membership only, never execution order and never Module creation. Every non-definition child has exactly one parent; membership is acyclic. The entry region and region definitions referenced by call/scan are separate roots of the containment forest. No factor may occur in two `contains` lists. Unreachable definitions are reported, not silently executed. Nested structural regions are permitted. A region is a factor with `contains` plus an interface. Region calls must form an acyclic call graph: recursive hierarchy is supported; runtime recursive calls, branches and unbounded while loops are not.

## Interfaces and edges
New interface form: `interface.<factor>.inputs` and `.outputs` are maps from port name to tensor specification. Specifications use `shape` as an ordered list of positive integer dimensions or declared symbolic dimensions, `axes` as an equally long list of unique axis labels, optional `dtype` and optional `name` for entry external tensor names. `interface.<entry>.symbols` maps symbols to `positive_integer`; shape equations go in `require` as a list of `same_shape(a,b)`, `equal_dim(a,i,b,j)`, or `divisible_dim(a,i,n)`. Port paths in these predicates are resolved in that factor's interface, and n is a positive integer. Dtype is otherwise inherited from inputs and operator rules; complex tensors must explicitly use complex64 or complex128. Fixture sizes and evaluation precision do not change symbolic architecture contracts.

An endpoint is `<factor>.<port>` or a declared entry external `name`. `dataflow` is a list of `[source,destination]`; list order does not impose execution. Each required input has exactly one producer, fan-out is allowed. Outputs may fan out. No implicit clone/detach/cast/reshape/projection/padding. A region input boundary is a source inside its region and a destination outside; its output boundary is a destination inside and source outside. Edges may connect siblings and region boundaries in their containing scope, never directly reach inside an unrelated region or definition. Same-step computational edges must be acyclic after expanding calls; scan carries are the only permitted temporal cycles. All ports resolve against explicit interfaces or the frozen v0.2 operator port rules. Additional outputs/intermediates must be explicit, not guessed.

## Calls and port binding
`factors.invoke.call: {region: body, inputs: {body_port: local_port}, outputs: {body_port: local_port}}` defines one call site. `interface.invoke` declares local ports; `interface.body` declares definition ports. Both bindings are total bijections over the respective body ports with identical shape/axes/dtype contracts under resolved symbols. Runtime values arrive at the call site's local input ports through ordinary dataflow; expansion binds those to body inputs, evaluates the body, and binds body results to local outputs. Binding is name association, not an extra tensor transform. Calls cannot read definition internals externally.
A definition's explicit Module and Parameter resource IDs remain global and shared across repeated invocations. Independent copies require distinct resource IDs and distinct factor/definition IDs. Calling the same definition twice never implicitly clones its resources.

## Module, Parameter, Buffer and alias identity
`resource: {factor_id: module_id}` retains exactly v0.2 meaning: equal IDs mean the very same Module, distinct IDs mean distinct Modules even with equal attributes. Only Module operators may have resource entries. Containers, call boundaries, scan boundaries and functional operators have no implicit Module. In v0.3 every Module operator requires a resource entry. Repeated Module IDs require consistent operator/attributes and internal bindings.
`parameters: {p_id: {shape: [...], dtype: float32, requires_grad: true, initialization: fixture_supplied}}` declares a trainable tensor identity. `requires_grad` may be false; allowed initializations are `fixture_supplied`, `zeros`, `ones`, or `module_default`. Dtype is optional when inherited from the creation context. `module_default` requires a bound Module slot whose frozen constructor defines initialization. `fixture_supplied` requires values supplied to both reference and candidate by the evaluator and does not encode test answers. Buffers use `buffers` with the same shape/dtype/initialization fields, plus `persistent` boolean and without `requires_grad`.
`parameter_bindings: {module_id: {slot_name: p_id}}` and analogous `buffer_bindings` bind real operator slots. Every actual Parameter and Buffer slot must be enumerated for v0.3 Module operators. Each slot resolves to one declared tensor ID. Equal IDs mean exact Python tensor object identity, not just equal values or storage; distinct IDs mean distinct objects and no storage alias under this candidate. Distinct Modules may bind the same Parameter ID. Sharing a Parameter does not merge Module identities or modes/buffers. Equal Module IDs must agree on all slot bindings. IDs do not prescribe `state_dict` keys.
Functional `linear` uses named input ports `input,weight` and optional `bias`, so tensor resource endpoints `parameters.<id>` and `buffers.<id>` are permitted as source-only endpoints. These endpoints create no operation. Their shape/dtype must agree with consumer ports. General views or partial storage alias between different Parameter IDs are not supported; propose a delta rather than treating storage overlap as object equality.
Parameters/buffers retain declared initialization semantics. A numerical fixture may overwrite aligned state on both sides; this does not prove initializers match. Module construction still follows the frozen PyTorch profile. Missing required initialization information blocks the claim about initialization, separately from forward fixture comparisons.

## State and scan
`state: {state_id: {shape: [...], axes: [...], initial: external}}` declares a logical carry, not a Module or Parameter. Its initial value must arrive at a declared scan input. No implicit zero state, learned initial state or cross-request cache. A zero/learned initial value must be built as an explicit dataflow value outside the scan.
A scan factor has `scan: {body: region_id, axis: integer, direction: forward|reverse, sequence_inputs: {body_port: {input: local_port, axis: integer}}, invariant_inputs: {body_port: local_port}, carries: {state_id: {input: local_initial_port, body_input: body_state_port, body_output: body_next_port, output: local_final_port}}, emits: {local_sequence_output: {body_output: port, axis: integer}}, empty: return_initial}`. Its own `interface` declares all local inputs and outputs.
All sequence inputs must have the same length on the declared nonnegative axes; top-level scan.axis equals the primary sequence input axis (first listed input) and is descriptive validation, not an extra slicing. Each iteration slices sequence inputs at the current index, binds invariants unchanged and binds previous carries to body inputs. Together these mappings cover every body input exactly once. Outputs are read once; next carry values are assigned simultaneously after body evaluation, never sequentially in map order. Every carry's input/output shape, axes and dtype match its state declaration; a body input cannot be both invariant and carry. No hidden detach.
Iteration k uses the same declared Module/Parameter identities at every time. New objects per iteration violate sharing. `direction: reverse` reads reversed sequence indices; emitted outputs are stacked in traversal order, and any restoration to source order is an explicit `flip`. `emits` stacks the selected body output at its declared axis; final carry outputs are separate. On an empty sequence, carry outputs equal initial inputs; empty emitted tensors have interface-declared shapes with length zero. This is the only allowed zero symbolic dimension: scan sequence length. A body output may feed both carry and emit. Body results that are unused must be reported.
Static positive-integer fixture counts may unroll a scan only as a declared scope restriction; unrolling never proves arbitrary-length recurrence. Autoregressive decoding with data-dependent stop conditions is outside this candidate.

## Dependency, stateful calls and mutation
`dependency` maps an output endpoint to a list of source endpoints describing required computational ancestry, as in the legacy Transformer sketch. It is an additional check on explicit expanded dataflow, not a replacement for missing edges or operator semantics. State dependencies across time must use scan carries. `dependency.order` is reserved and unsupported in this revision: graphs requiring extra read/write control order must propose a delta.
The original in-place/target semantics are unchanged. If two mutation/read operations are not uniquely ordered by tensor edges, the graph is BLOCKED under this candidate. Do not add an ordering, clone, or detach to make it executable. Module train/eval and running buffer state remain part of the operator profile; mutable Module calls must have an unambiguous order from dataflow/scan or be rejected.

## Frozen general tensor operator profile
`tensor_pytorch_2_2_1_v0_3_r1` includes the four unchanged v0.2 operators. All further operators below are functional with no Module identity. Declare every input/output port and shape in `interface` unless ports are stated below. All produce `output` unless stated otherwise. Explicit attributes are required where listed; numerical stability alterations and implicit masks are forbidden. Source mapping must verify these operations against the pinned local PyTorch source. Missing source-specific operators require delta review; names such as `lstm`, `attention`, `s4` and `mamba` are not primitives.

| Operator | Ports and PyTorch 2.2.1 meaning / required attributes |
|---|---|
| linear | input, weight, optional bias; `torch.nn.functional.linear`; attribute `bias` boolean controls port presence; weight is [out,in]. |
| matmul | left,right; `torch.matmul`, including its broadcast rules; contracts constrain intended ranks. |
| mul, sub, div | left,right; torch.mul/sub/div with default true division for div, no rounding_mode; div follows input dtype rules. |
| add | Original main,shortcut,output ports and inplace/target semantics, also for functional tensor profile. |
| sigmoid, tanh, exp, expm1, log, relu_functional, silu, softplus, conj, real, neg | input; corresponding torch function (relu/silu/softplus via torch.nn.functional); relu_functional and silu use inplace=false; softplus requires beta,threshold; real is torch.real. |
| softmax | input; torch.softmax, required dim; no implicit dtype conversion. |
| gelu | input; torch.nn.functional.gelu, required approximate=none or tanh; this is a new functional operator, not the edited ResNet GELU Module profile. |
| cat, stack | input0...inputK with K+1=`attributes.count` >=1, required dim; torch.cat/stack in numbered port order. |
| split | input; torch.split with required integer `sections` list and dim; output0...outputK for all sections, whose sum equals that input dimension. |
| reshape | input; torch.reshape with required shape list; at most one -1, other entries positive integers or bound shape symbols. No implicit transpose or contiguous copy assertion. |
| permute | input; torch.permute with required dims permutation. |
| transpose | input; torch.transpose with required dim0,dim1. |
| unsqueeze, squeeze | input; torch.unsqueeze/squeeze with required dim; squeeze requires the chosen axis size to be 1. |
| sum | input; torch.sum with required dim (integer or list) and keepdim boolean. |
| cumsum | input; torch.cumsum with required dim. |
| flip | input; torch.flip with required dims. |
| slice | input; Python slicing along required axis with integer start/stop (or null) and positive step; no advanced indexing. |
| clamp_min | input; torch.clamp_min, required numeric min. |
| masked_fill | input,mask; torch.masked_fill, required value numeric or literal string `-inf`; mask boolean with True meaning replace, broadcast follows PyTorch. Mask construction must be an external interface input or explicit operations. |
| layer_norm | input, optional weight,bias; torch.nn.functional.layer_norm; normalized_shape list, eps numeric, affine boolean; affine=true requires both tensor ports, false forbids them. |
| conv1d | input,weight, optional bias; torch.nn.functional.conv1d; stride,padding,dilation,groups integers, bias boolean; zero padding only; causal padding requires pad + slice explicitly. |
| pad | input; torch.nn.functional.pad; pad integer list, mode=constant, value numeric; no unspecified padding convention. |
| zeros_like, ones_like | input; torch.zeros_like/ones_like, inheriting dtype/device/layout, no requires_grad. |
| constant | No inputs; required numeric/list value and dtype; torch.tensor(value,dtype=...) on the input execution device; nontrainable constant, not a Parameter. Shapes are literal. |

All arithmetic follows the selected dtype, broadcasting and complex behavior of the pinned PyTorch profile. Shape algebra must be explicit; arbitrary executable strings or Python formulas inside YAML are forbidden. Closed-form SSM discretizations, masks, normalizers and gates must be decomposed into these primitives or reported as missing scope. This profile deliberately does not promise all structured S4 kernels, optimized CUDA scans, complex structured inverses, dropout/training randomness, cache protocols or data-dependent decoding.

## Legacy compatibility boundary
No new keys are required in old v0.2 files. Legacy `interface.block.input/output`, block root, unary ports, add ports, resource map and default initialization rules remain unchanged. The old LSTM/Seq2Seq/Transformer v0.1 sketches lack enough definitions and are historical evidence, not valid completed v0.3 representations. In particular `resource.step: theta_lstm_shared` must not be reinterpreted as a Parameter ID: its former ambiguity is recorded, then a new source-grounded representation explicitly declares functional Parameter references or actual Module bindings.
