# Common evaluation protocol — frozen revision 1
Each item receives PASS, FAIL, BLOCKED, or NOT_RUN with evidence paths and scope. PASS requires actual affirmative checks; FAIL is an executed check that found a violation; BLOCKED names a missing prerequisite; NOT_RUN means no execution. Do not collapse these into an aggregate success percentage or infer numerical/schema PASS from successful execution. A schema-expressibility BLOCKED result is useful research evidence.

1. **Pin source.** Choose one exact source artifact and minimal supported unit, record source path/URL, version/commit, file SHA-256, class/function and line spans, constructor options, source license if applicable, dependent operator sources and package metadata. Check installed source first. Missing sources stay Missing. No package install or unaudited pseudocode reference. Source facts, chosen restrictions and design choices must be separate in `source_mapping.md`.
2. **Freeze scope/fixtures.** Declare entry ports, symbolic layouts, concrete small CPU cases, dtype, modes, seeds, allowed length/shape domain, state initialization, parameter/buffer provenance, tolerances per output, intermediate hooks and unsupported behaviors in `fixtures/plan.json`. Default plan: CPU float32 eval, 1 torch thread, seeds 1701/1702/1703, rtol=1e-5 and atol=1e-6. Complex tests, if supported, declare precision/tolerances explicitly. Include nonzero states and nontrivial signed/nonzero parameters. No widening tolerance after observing generated output. Batch/time/feature sizes must differ in at least one case.
3. **Build independent oracle.** `reference.py` is authored/reviewed from pinned source, never from generated code or legacy LLM output. Cross-check source vs independent reference with aligned state and intermediate outputs for all fixtures; if source cannot run, record the limit and BLOCK source numerical grounding rather than calling it verified. A deliberate local specification can be studied only as a separately labeled specification-grounded scope, not substituted for missing architecture source.
4. **Write representation.** Ground every required operation/attribute/edge/port, resource/state/scan/dependency in source spans and YAML paths. Record omitted/full-source behaviors and information loss. Never reuse underdefined historical sketches as completed representations. Unknown semantics go to `schema_delta.md`; current frozen common semantics stay unchanged.
5. **Validator and negative controls.** Implement `validator.py --preflight` and `validator.py --candidate PATH --report PATH`. Use adapters/entrypoint metadata and semantic roles from runtime traces, not exact candidate class/attribute names, AST sentence equality or candidate assertions as proof. Source/static review still precedes execution. Validate hierarchy traceability, expanded dataflow, operator attributes, Module object identity, exact Parameter/Buffer sharing identity, state/carry/update timing, shape contracts and dependencies. A generated semantic_mapping is a hint to verify, never ground truth.
6. **Preflight before any API.** Demonstrate acceptance of source/independent reference and rejection of meaningful mutations: wrong edge/operator/attribute, broken sharing, dropped or swapped carry, wrong iteration axis/order, incorrect normalization/mask/state update as relevant. Every mutation must be exercised by a discriminating fixture; list detector, observed failure and non-vacuity evidence. Negative tests may use handcrafted models/graphs but no LLM-generated reconstruction. No applicable test set may be empty. Separate malformed-schema negatives from numerically wrong but executable model negatives.
7. **Freeze request/evaluation.** Hash source, reference, YAML, validator, negative tests, fixture plan, public/hidden tests and common manifest before request approval. Write `validation/preflight.json` with required fields described below. Build request offline using the shared utility. Review it for leakage. After approval, send exactly those hashed bytes once with the same model/settings/common prompt. No original Python, source mapping, reference, answers, tests or previous generated model in payload. The worker launch prompt is an instruction to Codex, never the LLM payload.
8. **Evaluate untouched response.** Preserve raw response, parse strict JSON, syntax-check, review entire source before import, extract code without repairs and record hashes. Determine candidate adapter independent of naming. No candidate import/instantiation before review. Compare structure and schema separately from execution.
9. **Align state and compare.** Map all reference and candidate Parameters and Buffers bijectively by semantic role plus sharing equivalence classes, not only matching shape/key names. Report extra/missing tensors and verify object identity, dtype, shape and exact copied values. Use identical inputs, initial carries, mode and aligned state in independent model instances. Check intermediate and final tensors including sequence/final state, max absolute/relative error, non-finite values and state mutation. All-zeros output alone is insufficient. Fixture transfer cannot prove initializer fidelity; test that separately or mark NOT_RUN. A failing/partial state mapping blocks numerical PASS.
10. **Report.** Write `validation/results.json` and `result.md` with per-axis statuses, evidence, scope, losses, failure category, schema delta use, blockers and open questions. No architecture-wide success from a single block/cell, no common schema success from per-worker custom extensions, no agent-edit claim from reconstruction. Evaluate train/grad only when explicitly in frozen scope; otherwise NOT_RUN.

## Required machine-readable preflight
`validation/preflight.json` has `status: PASS` only when all required preflight checks passed, `common_manifest_sha256`, `artifacts` (relative worker paths -> SHA-256), `checks` with PASS for `source_pinned`, `source_reference_match`, `source_to_yaml_mapping`, `schema_consistency`, `reference_acceptance`, `negative_tests`, `state_mapping`, and `fixture_nonvacuity`, plus evidence paths and `schema_delta_used: false`. All staged evaluation artifacts and representation are included in artifacts. Do not record status PASS if a mandatory prerequisite is missing. Freeze before presenting an approval request. Later changes invalidate it and require re-preflight and reapproval.

## Reporting axes and failure categories
Axes: source_grounding, representable_scope, structural_fidelity, dataflow_attributes, resource_identity, state_recurrence_dependency, numerical_fidelity, schema_consistency; additionally source_reference_match and validator_preflight. Initial states are NOT_RUN. Empty or unsupported axes use BLOCKED plus reason, not PASS by absence.
Failure categories: SOURCE_MISSING, SOURCE_VERSION_UNPINNED, SOURCE_REFERENCE_MISMATCH, REPRESENTATION_INFORMATION_LOSS, SCHEMA_UNSUPPORTED, SCHEMA_INCONSISTENT, PREFLIGHT_FAILED, API_APPROVAL_PENDING, API_TRANSPORT, RESPONSE_FORMAT, GENERATED_SYNTAX, GENERATED_RUNTIME, STRUCTURE_MISMATCH, PARAMETER_MAPPING, STATE_DEPENDENCY, NUMERICAL_MISMATCH, ENVIRONMENT_UNAVAILABLE. Multiple categories are allowed. Failure and limitation must remain distinct.
