# 실험을 이어가는 방식

README에는 현재 연구 질문, 대표 사례, 다음 비교 실험만 짧게 남깁니다. 상세 조건과 실패 분석은 해당 실험 폴더에서 관리합니다.

새 실험은 기존 폴더를 덮어쓰지 않고 별도 ID로 추가합니다. 예: `experiments/transformer-registration-v2/`. 생성 코드 자체를 고쳤다면 기존 LLM 출력과 구분해 별도 후보로 기록합니다.

각 실험에는 다음을 연결합니다.

1. **질문과 변경점:** 앞 실험에서 무엇을 바꿨으며, 무엇을 비교하는가?
2. **입력:** YAML, 명세 버전, 생성 프롬프트와 모델 설정.
3. **후보:** 실제 생성 코드, 인터페이스, 생성 이후 수정 여부.
4. **평가:** 검증 코드, 입력 조건·seed·허용오차, 환경과 실행 방법.
5. **결과:** 원본 보고서, 항목별 판정, 한계와 다음 질문.

자료를 추가할 때 `experiments/manifest.json`에 원본 상대 경로·SHA256·공개본 SHA256·변환 내용을 남기고, 실험 인덱스와 사례 문서, `results/summary.md` 및 `results/summary.json`을 함께 갱신합니다. README는 연구 방향이나 대표 사례가 달라질 때 바꿉니다.

원래 실패를 후속 성공으로 덮어쓰지 않습니다. 검증 조건을 바꾼 평가, 사후 진단, 새로 생성한 후보는 별도 결과입니다. 변경 이유를 `CHANGELOG.md`에 짧게 기록합니다.
