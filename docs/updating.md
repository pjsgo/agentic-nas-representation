# 자료 업데이트

공유 저장소의 프로젝트 폴더와 개인 저장소 루트는 같은 `architectures/`, `relations/`, `specs/`, `docs/` 구조와 내용을 사용합니다. 다른 사람의 폴더에 대한 공동 작업용 연결이 필요하면 별도로 명시하고, 개인 배포에는 포함하지 않습니다.

- 아키텍처 추가 또는 계산 수정: 해당 폴더의 YAML, 최종 구현, 사용 계약, 출처와 `architectures/catalog.json`을 갱신합니다.
- 관계 추가 또는 매핑 수정: 관계 YAML과 `relations/catalog.yaml`을 갱신하고 양쪽 부품 ID를 확인합니다.
- 공통 해석 규칙 변경: `specs/`에서 버전을 구분하고 영향을 받는 YAML의 참조를 갱신합니다.
- 설명과 예시 개선: `docs/`와 해당 아키텍처 README를 수정합니다.

복원 범위를 제한한 경우 해당 자료에 포함 및 제외, 미해결 부분을 기록합니다. 기존 명세로 그 내용을 표현할 수 없다면 명세를 확장합니다. 생성 원본과 수정본의 판정은 구분합니다.

공개 자료에는 사용과 해석에 필요한 정보만 둡니다. 원본 프롬프트, API 응답, 실험 로그, fixture, 상세 평가 보고서, 과거 구현 사본은 연구 작업 공간에서 관리합니다. README에는 세션 진행 상황이나 작업 계획을 적지 않습니다.

설명문에는 중간점을 사용하지 않습니다. 항목은 쉼표로 구분하거나 접속사를 넣어 자연스러운 문장으로 작성합니다.
