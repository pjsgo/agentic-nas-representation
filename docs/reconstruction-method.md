# YAML 기반 아키텍처 복원 방법

**복원 LLM에는 YAML에 명시된 계산을 구현하도록 요청합니다. 아키텍처 이름이나 익숙한 구조로 빠진 계산을 보충하지 않도록 지시하며, 정의가 부족하면 불명확한 부분을 보고하게 합니다.**

구조를 결정하는 기준은 YAML과 그 해석 규칙입니다. 코드를 연결하기 위한 입출력 및 파라미터 전달 계약도 함께 제공합니다. 따라서 여기서 YAML 기반 복원은 YAML 파일 하나만 전달했다는 뜻이 아니라, 선언된 계산과 계약을 구현의 기준으로 삼았다는 뜻입니다.

## 정보 제공 범위

| 단계 | 사용하는 정보와 역할 |
|---|---|
| 표현 작성 | 연구자가 논문과 공식 코드에서 핵심 계산과 범위를 확인하고 YAML로 기술 |
| LLM 코드 생성 | 복원 YAML, 표현 및 연산 해석 규칙, 구현 인터페이스와 응답 형식 제공 |
| 독립 평가 | 생성에 제공하지 않은 참조 구현과 평가 입력, 기대 결과로 비교 |

원본 아키텍처 코드, 독립 참조 코드, 평가 입력값, 기대 출력, 숨겨진 검사 내용을 복원 요청의 정답 자료로 제공하지 않습니다. 변수명과 클래스 구성 등은 선택할 수 있지만, 선언된 연산과 연결, 파라미터 공유, 상태 전달의 의미는 보존하도록 요청합니다.

이는 생성 시 허용한 정보와 요구한 동작에 대한 설명입니다. 프롬프트 지시만으로 LLM 내부의 사전지식 사용이 완전히 배제됐음을 증명하지는 않습니다. 공통 원칙 아래 대상별 계약을 명시했으며, 모든 실험이 동일한 프롬프트와 평가 조건을 사용한 것은 아닙니다.

## 복원 범위와 완료 기준

복원 대상은 전체 모델 또는 명시한 block/core입니다. 포함 및 제외 범위와 외부에서 공급하는 입력, 파라미터, 초기 상태를 구분합니다. 아키텍처의 특징을 제거한 일반 연산만으로 복원을 완료했다고 판단하지 않습니다.

코드 실행이나 출력 shape의 일치만으로 완료를 판단하지 않고, 선언된 범위에 필요한 항목을 함께 확인합니다.

- **핵심 계산:** 특징적인 연산과 연결, 반복, 갱신 순서의 보존
- **출력:** 독립 참조와 허용 오차 내 일치, 출력 구조, shape, dtype 확인
- **파라미터, 자원:** 필요한 값, 공유, 등록, 변경 여부의 계약 준수
- **상태:** 초기 상태 반영, 갱신, 반환 및 필요한 연속 호출 계약 준수

참조는 후보를 호출하거나 후보의 계산 함수를 공유하는 자기 비교가 되지 않도록 구성합니다. 같은 입력, 파라미터, 초기 상태, 실행 모드에서 비교하며, 수치 일치와 별도로 출처에 근거한 핵심 계산도 확인합니다. 연구용 실현기의 성공을 외부 LLM 생성 코드의 성공으로 대신하지 않습니다.

사례 수, dtype, 허용 오차와 세부 확인 항목은 대상별 근거를 따릅니다. 완료 표시는 해당 범위와 기준에서 확인했다는 뜻이며, 전체 자료를 하나의 동일한 엄격 검사로 인증했다는 의미는 아닙니다.

## 생성 결과와 수정의 구분

생성 원본과 평가 기록을 보존하고, 수정본은 변경 이유와 함께 구분합니다. 공개한 최종 코드의 출처는 각 아키텍처의 `provenance.json`에서 확인합니다.

- 생성 코드를 수정하지 않은 결과와 수정 후 확인한 결과를 구분합니다.
- 명확화, 후속 요청의 이력을 보존하며, 최종 성공을 최초 시도 성공으로 바꾸지 않습니다.
- 응답 형식 처리와 계산 수정은 구분합니다. 평가용 연결 코드에서 누락된 계산을 몰래 보충하지 않습니다.
- 제외, 미해결 부분을 명시하며, 범위 제한이나 명세 확장으로 과거 실패를 소급해 성공 처리하지 않습니다.

## 결과의 해석 범위

작은 사례의 계산, 계약 확인은 모든 입력에 대한 증명, 전체 모델의 학습, gradient 동등성, 품질, 속도, 메모리 성능 재현을 뜻하지 않습니다. 관계 작성, 부품 매핑과 실행 가능한 모델 변환도 구분합니다.

이 저장소는 복원 자료와 공통 방법을 설명합니다. 모든 요청 원문, fixture, 검사기를 포함한 완전한 실험 재실행 묶음은 아닙니다. 개별 생성 설정, 코드 출처와 확인 범위는 아키텍처별 기록을 따릅니다.
