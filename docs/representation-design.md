# 신경망 구조 표현 설계

핵심 질문은 “구조화된 설명에서 코드를 다시 만들 때, 선택한 아키텍처의 의미를 보존하려면 어떤 정보가 필요한가?”입니다. 여기서 의미를 보존한다는 것은 출력값뿐 아니라 연산 순서, 상태 전달, 객체 공유와 입력 변경 여부도 요구 범위 안에서 유지한다는 뜻입니다.

## 표현에 포함하는 정보

| 구성 요소 | 표현하려는 의미 | 피해야 할 오류 |
|---|---|---|
| 계층과 영역 | 요소의 소속 관계와 이름이 있는 경계 | 묶여 있다는 이유만으로 실행 순서나 Module 객체를 추정하는 것 |
| 연산과 속성 | 버전이 정해진 연산 정의에 따른 계산 | 빠진 동작을 아키텍처 이름에 대한 사전지식으로 채우는 것 |
| 데이터 흐름 | 이름이 있는 포트 사이의 직접적인 텐서 전달 | 명시되지 않은 reshape, cast, clone, detach를 추가하는 것 |
| 자원·객체 동일성 | 같은 Module 객체를 재사용하는지, 다른 객체를 사용하는지 | 값이 같다는 이유로 객체도 공유한다고 판단하는 것 |
| Parameter·Buffer 동일성 | 유지해야 할 텐서의 역할과 객체 구분 | 학습 가능한 Parameter를 일반 텐서로 바꾸는 것 |
| 상태와 반복 | 초기 상태, 상태 전이, 시퀀스 출력, 최종 상태 | 상태 전달, 시간축 공유, 빈 시퀀스 동작을 빠뜨리는 것 |
| 의존관계와 변경 대상 | 읽기·쓰기 순서와 제자리 변경 대상 | 외부 입력을 잘못 변경하거나 읽기·쓰기 순서를 뒤섞는 것 |
| 입출력 규약 | 텐서 포트, 축, shape와 값의 범위 | 정적 제약을 근거로 임의의 보정 연산을 추가하는 것 |

표현 규칙은 실험별 버전으로 관리합니다. BasicBlock 실험은 v0.2와 별도의 GELU 연산 정의 확장을 사용했습니다. 이후 6개 아키텍처 작업은 사전에 고정한 v0.3 후보 명세를 사용했습니다. Transformer의 등록 방식 제안은 그 뒤의 별도 실험용 추가 명세입니다. 이들을 모든 아키텍처에서 검증이 끝난 하나의 공통 스키마로 취급하지 않습니다.

## 같은 객체를 쓴다는 것은 무엇인가

BasicBlock 기준 모델은 **같은 ReLU 객체를 두 번 호출**합니다. 지정된 편집에서는 첫 ReLU를 유지하고, 잔차를 더한 뒤에는 별도의 GELU 객체를 사용합니다.

이 편집을 일관되게 나타내려면 연산 이름뿐 아니라 속성과 객체 연결도 바꾸고, GELU의 해석 규칙을 정의해야 합니다. 따라서 이 결과는 YAML의 아무 문자열 하나만 바꾸면 항상 올바르게 편집된다는 근거가 아닙니다.

## 현재 표현의 한계

여러 연산을 하나의 영역으로 묶었다고 원본 Python Module의 계층이나 객체 동일성이 자동으로 보존되지는 않습니다. Linear Transformer에서 공유하는 상태 없는 feature-map Module이 대표적인 사례입니다. 수치 출력은 같더라도 공유 객체를 두 객체로 나누면 객체 구조는 달라집니다. 원본 전체의 객체 동일성을 나타내는 문제는 현재 BLOCKED로 남아 있습니다.

이 문서는 설계 개념의 요약입니다. 실제 [고정 명세](../specs/schema_v0_3_candidate.md)와 [실험별 YAML](../experiments/README.md)을 함께 제공합니다. ResNet은 v0.2를 사용하며 해당 폴더의 vocabulary.md를 기준으로 읽습니다.
